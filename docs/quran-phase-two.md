# المرحلة الثانية: ربط التفسير بالطلب الحالي

## النطاق

منع ظهور تفسير طلب سابق تحت عنوان آية أخرى. لا تغييرات على نص القرآن أو ملفات التفسير المضمّنة أو الصوت أو التنزيلات.

- فصل تحميل التفسير في `useQuranTafsir`، مع هوية تشمل المصدر والسورة والآية ورقم طلب متزايد.
- إلغاء الطلب السابق بإشارة AbortController عند فتح آية أخرى أو إغلاق النافذة أو تغيير السورة أو المصدر أو فك التركيب.
- التحقق من هوية الطلب بعد كل انتظار، حتى إذا تجاهل النقل الإلغاء، وقبل كتابة الكاش أو إظهار النص أو الخطأ.
- مسار الكاش يضبط التحميل إلى false، ولا يبقى عالقًا خلف طلب سابق.
- عرض النتيجة مشروط بهوية اختيارها؛ عنوان المصدر مرتبط بنفس الاختيار.
- التحقق من السورة ورقم الآية إذا أعادهما مزود الإنترنت؛ رفض الرد غير المطابق بدل نسبته إلى آية أخرى.
- التخزين غير المتاح لا يمنع عرض نتيجة صحيحة.

عند تغيير المصدر أو الإعدادات تُغلق نافذة التفسير، ثم يُستخدم المصدر المختار عند فتحها من جديد.

## التحقق

- TypeScript strict ناجح.
- 477 اختبارًا في 51 ملفًا ناجحة، منها 12 اختبارًا جديدًا لملكية طلب التفسير.
- تغطية الردود المعكوسة، الكاش أثناء طلب معلق، فشل الطلب القديم والحالي، الإغلاق، فك التركيب، تغيير السورة والمصدر، تأخر جسم JSON، التفسير المحلي الأوفلاين، وهوية رد خاطئة.
- بناء الإنتاج مع PRERENDER=1 ناجح. تحذير localStorage أثناء التصيير المسبق موجود ضمن مسار الإعدادات القديم ولا يمنع البناء.
- تحقق Chrome فعلي بعرض 390×844: طلب الآية الأولى مؤخر مع تجاهل إلغاء النقل، ثم إغلاقه وفتح الآية الثانية من الكاش، ثم تحرير الرد القديم. ظل العنوان والنص للآية الثانية دون تحميل عالق. النص المصوّر موسوم بوضوح بأنه نص اختبار وليس تفسيرًا حقيقيًا.
- تحقق بصري من نافذة التفسير الميسر المضمّن، مع صفر أخطاء JavaScript غير معالجة في السيناريوين.

الشبكة في اختبار السباق محاكاة مضبوطة. لم يُبن APK ولم يُختبر هاتف أندرويد. هذا إصلاح منطق ويب مع اختبارات، وليس إثباتًا لكل سلوك WebView على جهاز.

## إعادة الاختبار

```sh
npm ci
npm run validate:quran-pages
npm run typecheck
npm run test:run
PRERENDER=1 npm run build
```

المرحلة الأولى موجودة على main-2 قبل هذا التغيير. يبقى main دون تعديل، ولا يبدأ أي عمل من المرحلة الثالثة.
