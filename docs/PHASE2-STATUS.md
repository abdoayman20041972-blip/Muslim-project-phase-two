# حالة مشروع «مسلم» — المرحلة الثانية (نسخة APK v1.2.0)

> **هذا هو الملف المرجعي الحالي للبنية والمسار.** الوثائق الثلاث الأخرى في هذا المجلد
> (`MUSLIM_ARCHITECTURE_HANDOFF.md`، `MUSLIM_HANDOFF_CURRENT.md`، `CLAUDE_REVIEW_GUIDE.md`)
> تعود إلى **المرحلة الأولى** (Convex / VAPID / Push خادمي / مستودع Azkar-app-) وتصف
> معمارية **لم تعد موجودة**. لا تُبنَ عليها أي قرار؛ تُقرأ لأغراض تاريخية فقط.

## ما هذه النسخة

نسخة **APK نقية** من تطبيق مسلم: كل آثار الويب (service worker، manifest، إشعارات
Push الخادمية، Macaly bridge) حُذفت، وكل محتوى غير القرآن أصبح يعمل **أوفلاين بالكامل**.
القرآن وحده يحتاج الإنترنت (نص التفسير الإضافي والتلاوة والتنزيل الاختياري للسور)، مع
نص المصحف العثماني والتفسير الميسر مدمجين محليًا.

## البنية الفعلية (ما يعمل به الكود اليوم)

- **الإشعارات**: إشعارات محلية أصلية عبر ملحق Capacitor LocalNotifications —
  `src/app/features/notifications/nativeNotifications.ts` هو المرجع الوحيد.
  الجدولة تعتمد الحساب الفلكي المحلي (مكتبة `adhan`) بلا أي اتصال شبكة، بأفق 30 يومًا،
  وتتضمن `USE_EXACT_ALARM`/`SCHEDULE_EXACT_ALARM`. وحدات الويب القديمة
  (`useIslamicNotifications`/`usePrayerReminders`/`notifications.ts`) **حُذفت**.
- **المواقيت**: الحساب المحلي هو الأساس (`prayerTimings.ts` عبر `adhan`) مع Aladhan
  كبديل تحسيني فقط.
- **التخزين**: مزامنة ثنائية localStorage ↔ SharedPreferences (`preferencesMirror.ts`).
- **الصوت في الخلفية**: إضافة Java مخصصة `plugins/capacitor-background-audio`
  (خدمة MediaSession أمامية).
- **البناء**: GitHub Actions `Build Android APK` (تشغيل يدوي workflow_dispatch) ببناء
  إنتاجي مُحسَّن: `PRERENDER=1 npm run build` — لم يعد يستخدم DEV_BUILD.
- **الويب لم يعد هدفًا**: لا نشر ويب، لا CSP، لا PWA. إن أُريدت نسخة ويب مستقبلًا
  فستحتاج إعادة إدخال manifest وsw وسياسة _headers من تاريخ git.

## قواعد العمل (دليل المراجعة القديم ما زال ساريًا في جوهره)

- لا تعديل دون قرار صريح من صاحب المستودع، بندًا واحدًا لكل أمر.
- تحقق قبل وبعد كل التزام: `npm run typecheck` ثم `npm run test:run`.
- الاختبارات والتحقق النوعي **حاجبان** الآن لبناء الـ APK في سير العمل.
